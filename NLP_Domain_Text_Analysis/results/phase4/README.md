## Relevance judgments

- Judge pool depth: **10** retrieved units per query
- Pairs judged: **166** (155 relevant, 11 not relevant)
- Annotator: single annotator: implementing author (Phase 4)
- Method: pooled manual judgment; rubric recorded per row in the notes column

Rubric:

```
relevance = 1 when the content unit's own text substantively discusses the
query's concept in an economic or financial sense - it would be a useful
answer to "what does this corpus say about <query>".
relevance = 0 when the unit matches only lexically: a table cell, a passing
enumeration, a chart label, a boilerplate footer, a coincidental number, or a
mention that the unit itself does not develop.
A unit is judged on its own text, not on its rank or its score.
```

A label is never derived from a similarity score. A metric computed from the
same function it is meant to evaluate would not measure anything.

### How to read the recall figure

Relevance labels are human judgments over a pooled candidate set of depth 10. Recall is measured against the judged relevant set and is therefore bounded by the pool; precision at the judged depth is exact because every considered unit carries a label.

## Reproducing

```
python -m src.phase4.run
```

The run is deterministic: the query set, the pooling depth and the Phase 3
ranking are all fixed, and ties in Phase 3 are broken by `unit_id` ascending.
